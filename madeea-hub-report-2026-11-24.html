End-of-day reports by email to the team leads

Reichelle and Rowena asked on 19 October to receive each end-of-day report by email. The Hub side was ready on 5 November; the email itself is now built and switched on.

  • How it works: when an assistant submits their report, the Hub hands it to the team's automation service (n8n), which emails both team leads from "MadeEA Hub". The email shows the assistant's name, the date, what was done, any blockers and the plan for tomorrow, with a link to the reports in the Hub.
  • One email per assistant per day. A correction later that day updates the report in the Hub without sending a second email.
  • Secured: the automation only accepts calls carrying a secret key shared with the Hub. Calls without it are refused.
  • A snag found while testing: the server running the automation blocks the usual email port, so the first test timed out after 4 minutes. It now uses the email service's alternative port, and the test email arrived.
  • Tested first in the test team, sending to our own inbox, then switched on for the real team. It stays off for the test team, so automated tests never email the team leads. Reichelle and Rowena have been told it is coming.

AI costs in dollars, with an alert

The last open items from the analytics plan are done.

  • Prices: every AI model the Hub uses already had its price set (since 6 November), so each AI action records its cost in dollars. No change was needed.
  • The AI dashboard showed "cost per user per day", but it was actually counting words processed (tokens). It now shows dollars: the most anyone has spent in a day is under one cent.
  • The "AI cost spike" alert checks every morning and warns if anyone averages over $0.25 a day, half the $0.50 daily cap each person already has. A "50% increase" rule was considered but would fire almost every day while use is still occasional.
  • All three planned alerts are now set: end-of-day reports under 60%, AI errors over 2% an hour, and AI cost.

Why Hub emails reach madeeas.com Spam, and the fix

Tested today with a madeeas.com mailbox:

  • Without a filter, Hub emails (sign-in, password resets, reports) can land in Spam. A Gmail filter that never sends madeea.io to Spam fixes that, and is set up on two mailboxes so far.
  • Even in the Inbox, Gmail shows a red "This message might be dangerous" warning. That is madeeas.com's own protection: madeea.io looks very like madeeas.com, so Gmail treats it as a possible fake. Clicking "Looks safe" clears it for one person.
  • The fix for everyone is two settings in the madeeas.com Google Admin console: add madeea.io as an approved sender, and stop the lookalike-domain warning for it. This is safe because Hub mail passes the standard sender checks. The request, with step-by-step instructions, is ready to send to the admin, along with a one-minute filter guide for the team in the meantime.
