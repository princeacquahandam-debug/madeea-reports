Grokbot's check of Approvals

The Approvals page went live on 23 November. Today Grokbot ran it end to end in the test team, with the test owner, assistant and client: 16 steps, from ticking "Needs approval" to the client's view.

  • Passed: the bell for approvers and for the assistant, the three lists, Send back with a reason (the button stays off until a reason is typed), Approve with who and when, resubmitting, completing approved work, and assistants kept out of the Approvals page.
  • Private from the client: the send-back reason and its comment were not visible in the client portal.
  • The one gap: moving an unapproved task to Done was correctly refused, but nothing said why. The card simply slid back, which looked like a glitch.
  • Verdict: "Ready with one fix". Two smaller suggestions came with it, both done below.
2Live

A clear message when Done is refused

When someone tries to complete a task that still needs approval, the Hub now keeps it where it was and says:

"…needs an owner or admin to approve it before it can be marked Done. Move it to Review and they'll see it in Approvals."

  • Every way in: dragging the card to Done, the tick on the card, choosing Done in the edit window (other changes in the window still save), and accepting an AI "Prioritize board" suggestion.
  • No flicker: the card goes straight back instead of briefly showing in Done.
  • Tested on a local copy and again on hub.madeea.io after it went out: the message showed for the tick, the edit window and dragging, and the task stayed unfinished each time. The AI path has the same check but wasn't run, as that would use an AI request.
3Live

Tidier Sent back list, and "Resubmitted"

  • Sent back list: items waiting on the assistant no longer show Approve and Send back, since there's nothing to approve yet. They move back to Waiting when the assistant resubmits.
  • "Resubmitted": once sent-back work is moved to Review again, it no longer says "Sent back". The task card, the task's edit window and the Approvals page now say Resubmitted, and keep the earlier feedback as history ("Earlier sent back by … : …").
  • Tested locally and live: assistant submits, owner sends back, the card says Sent back; assistant resubmits, the card, edit window and Approvals all say Resubmitted.
